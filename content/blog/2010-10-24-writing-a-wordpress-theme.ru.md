Темы, которые люди скачивают, велики потому, что пытаются быть похожими на всё сразу. Минимум, который WordPress примет как тему, — это два файла, и понимание этих двух делает читаемой любую большую тему. Вот тема, собранная с нуля, вместе с той единственной идеей, на которой построено всё остальное в теме.

## Два обязательных файла

Создайте `wp-content/themes/bare/` и положите туда `style.css`, начинающийся с блока комментария. Как и в случае с плагинами, WordPress читает именно комментарий; остальная часть файла — обычный CSS:

```css
/*
Theme Name: Bare
Description: The smallest theme that works.
Author: Mark Veltzer
Version: 0.1
License: GPL2
*/

body { max-width: 40em; margin: 2em auto; font-family: serif; }
```

Второй файл — `index.php`, и это запасной вариант для любой страницы, которую может показать сайт. Когда есть только эти два файла, тема появляется в разделе Appearance, и её можно активировать.

## Цикл

Всё, что делает тема, вращается вокруг одной конструкции. Ещё до того, как запустится ваш шаблон, WordPress уже определил, какие записи относятся к этому запросу: одна запись, страница, последние десять, всё по метке, всё за месяц. Ваша задача — пройтись по ним. Этот проход называется циклом (the loop), и вот он:

```php
<?php get_header(); ?>

<?php if (have_posts()) : ?>
    <?php while (have_posts()) : the_post(); ?>
        <article>
            <h2><a href="<?php the_permalink(); ?>"><?php the_title(); ?></a></h2>
            <p><?php the_time('Y-m-d'); ?></p>
            <?php the_content(); ?>
        </article>
    <?php endwhile; ?>
<?php else : ?>
    <p>Nothing here.</p>
<?php endif; ?>

<?php get_footer(); ?>
```

`have_posts()` спрашивает, осталось ли что-нибудь, `the_post()` загружает следующую запись, а каждая функция, начинающаяся с `the_`, печатает что-то о записи, загруженной в данный момент. Вот и вся модель. Тема, показывающая одну запись, и тема, показывающая архив, выполняют один и тот же цикл; разница лишь в том, какие записи ей передал WordPress.

## Шапка и подвал

`get_header()` подключает `header.php`, а `get_footer()` — `footer.php`. Если держать их отдельно, ими могут пользоваться все шаблоны:

```php
<!DOCTYPE html>
<html <?php language_attributes(); ?>>
<head>
    <meta charset="<?php bloginfo('charset'); ?>">
    <title><?php wp_title('|', true, 'right'); bloginfo('name'); ?></title>
    <link rel="stylesheet" href="<?php bloginfo('stylesheet_url'); ?>">
    <?php wp_head(); ?>
</head>
<body>
<h1><a href="<?php echo home_url(); ?>"><?php bloginfo('name'); ?></a></h1>
```

и подвал:

```php
<?php wp_footer(); ?>
</body>
</html>
```

`wp_head()` и `wp_footer()` — не украшение. Плагины цепляются к этим моментам, чтобы вставить свои скрипты и таблицы стилей, так что тема, которая их опускает, ломает половину плагинов на сайте.

## Иерархия шаблонов

Теперь у вас есть тема, и она показывает всё через `index.php`. Чтобы обрабатывать некоторые запросы иначе, добавьте файл с правильным именем, и WordPress автоматически выберет его вместо `index.php`:

- `single.php` для одной записи, `page.php` для одной статической страницы
- `archive.php` для архивов по датам, рубрикам и меткам; `category.php` и `tag.php`, если хотите их разделить
- `home.php` для списка на главной странице, `front-page.php`, когда главная — статическая страница
- `search.php` и `404.php` — для того, что сказано в их названиях

Каждый из них содержит тот же цикл. Иерархия — это соглашение об именах, а не модель программирования, и файлы можно добавлять по одному по мере надобности.

## functions.php

Если в каталоге темы есть `functions.php`, WordPress загружает его раньше всего остального, и он ведёт себя в точности как плагин, поставляемый вместе с темой. Используйте его, чтобы включать возможности и правильно подключать таблицы стилей:

```php
<?php
function bare_setup() {
    add_theme_support('post-thumbnails');
    add_theme_support('automatic-feed-links');
    register_nav_menu('main', 'Main menu');
}
add_action('after_setup_theme', 'bare_setup');

function bare_styles() {
    wp_enqueue_style('bare', get_stylesheet_uri());
}
add_action('wp_enqueue_scripts', 'bare_styles');
```

Когда таблица стилей подключена таким образом, строку `<link>` из `header.php` можно убрать: её напечатает `wp_head()`. Всё, что меняет поведение, а не внешний вид, должно жить в плагине, а не здесь, потому что функции темы исчезают в тот момент, когда вы переключаете тему.

## Откуда берётся размер

Коммерческая тема — это этот скелет плюс страница настроек, дюжина файлов шаблонов, области виджетов и уйма CSS. Ничто из этого не меняет модели: WordPress выбирает записи, иерархия шаблонов выбирает файл, файл выполняет цикл, а функции `the_` печатают. Читайте любую тему, держа это в голове, и она перестанет пугать.

Отдавайте веб-серверу весь каталог только для чтения, как и всё остальное в `wp-content`; почему — я описал в [одном из прошлых постов](@/blog/2010-07-09-wordpress-unix-security-2.md).
