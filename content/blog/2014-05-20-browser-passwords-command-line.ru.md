Каждый браузер предлагает запомнить ваши пароли, и большинство людей соглашается. Стоит точно знать, куда эти пароли попадают и как мало отделяет их от любого, кто может выполнить команду от вашего имени. В этой заметке показано, как прочитать сохранённые пароли Firefox и Chrome из оболочки в Linux. Смысл отчасти практический — скрипт, который их читает, отлично подходит для переезда между браузерами или для ревизии того, что у вас сохранено, — и отчасти предостерегающий.

## Где их хранит Firefox

Firefox хранит логины в каталоге профиля, в `~/.mozilla/firefox/<profile>/`. Важны два файла:

- `logins.json` содержит сайт, имя пользователя и пароль, причём последние два зашифрованы.
- `key4.db` (в старых профилях `key3.db`) — база SQLite с ключом, которым они расшифровываются.

Шифрование настоящее, но ключ лежит рядом с данными. Если вы не задали мастер-пароль, сам ключ защищён пустым паролём, а значит, всё устройство — это сокрытие, а не защита.

Чище всего прочитать их скриптом `firefox_decrypt` — небольшой программой на Python, которая читает оба файла и использует библиотеку NSS, поставляемую самим Firefox:

```bash
git clone https://github.com/unode/firefox_decrypt.git
cd firefox_decrypt
python firefox_decrypt.py
```

Он выводит список ваших профилей, спрашивает мастер-пароль, если он у вас есть, и печатает все сохранённые логины. Чтобы получить машиночитаемый вывод для переезда:

```bash
python firefox_decrypt.py --format csv > ~/firefox-logins.csv
```

Если хотите посмотреть на исходные куски, открытая половина — это просто JSON:

```bash
python -m json.tool ~/.mozilla/firefox/*.default/logins.json | grep -E 'hostname|encryptedUsername'
```

## Где их хранит Chrome

Chrome хранит логины в базе SQLite:

```text
~/.config/google-chrome/Default/Login Data
```

Имена пользователей и адреса лежат открыто. Пароли зашифрованы ключом, который Chrome передаёт связке ключей рабочего стола через libsecret, так что в GNOME или KDE ключ живёт в вашей связке и разблокируется при входе в систему. Сначала скопируйте базу, потому что Chrome держит её заблокированной, пока работает:

```bash
cp ~/.config/google-chrome/Default/Login\ Data /tmp/login-data.db
sqlite3 /tmp/login-data.db 'select origin_url, username_value from logins;'
```

Чтобы получить и пароли, нужна запись из связки ключей. Если установлены инструменты `libsecret`:

```bash
secret-tool lookup application chrome
```

печатает ключ, который использует Chrome. Расшифровать им каждое `password_value` — это несколько строк на Python с `pycryptodome` (AES в режиме CBC, фиксированная соль и фиксированное число итераций, которые задокументированы в исходниках самого Chrome); в сети есть несколько небольших скриптов, делающих ровно это, и подойдёт любой из них. Если Chrome был запущен с `--password-store=basic`, связки ключей нет вовсе, и пароли хранятся в виде, который любой скрипт откроет напрямую.

## О чём это говорит

Перечитайте оба раздела и заметьте, что у них общего. **Пароли защищены от постороннего, укравшего диск, и ни от кого, кто может выполнить команду от вашего имени.** Любая запущенная вами программа, любой скрипт, который сайт обманом заставил вас выполнить, любой коллега, севший за ваш незаблокированный стол, выведет их все за секунду.

Три следствия:

- Задайте мастер-пароль в Firefox, если машина когда-либо остаётся без присмотра и незаблокированной. Это единственное, что превращает сокрытие в шифрование.
- Блокируйте экран. Для Chrome на работающем рабочем столе это вся защита целиком.
- Относитесь к хранилищу сохранённых паролей как к удобству с той же безопасностью, что у текстового файла в домашнем каталоге, потому что это оно и есть. Настоящий менеджер паролей, со своей парольной фразой и базой, запирающейся при простое, — вещь совсем другого разряда.

Приведённые выше команды — те же самые, которыми воспользовался бы злоумышленник. Знание их и есть причина отнестись к этим трём пунктам всерьёз.
