Большинство советов по резервному копированию велят копировать ваши файлы. Для ваших данных это верно, но для самой системы модель неверная. Установка Debian или Ubuntu почти целиком восстанавливается из архива: пакеты лежат там, готовые к переустановке. Невосстановим небольшой набор решений, которые приняли вы, и именно его должна сохранять резервная копия системы. Трёх вещей достаточно, чтобы воссоздать характер машины.

## Три команды

```bash
# 1. The configuration you edited: everything under /etc.
sudo tar --create --bzip2 --absolute-names \
    --file "/tmp/etc.$HOSTNAME.tar.bz2" /etc
cp "/tmp/etc.$HOSTNAME.tar.bz2" "$FOLDER"
sudo rm "/tmp/etc.$HOSTNAME.tar.bz2"

# 2. Which packages are installed. Any user can run this.
dpkg --get-selections > "$FOLDER/dpkg_selections.$HOSTNAME.txt"

# 3. Which alternative each choice points at (editor, java, and so on).
update-alternatives --get-selections > "$FOLDER/alternatives.$HOSTNAME.txt"
```

Перед запуском задайте в `FOLDER` то место, где хранятся ваши резервные копии.

## Для чего каждая строка

**tar каталога `/etc`** сохраняет конфигурацию, которую вы действительно трогали: сетевые настройки, fstab, ключи и конфигурацию ssh, задания cron, отредактированную вами конфигурацию пакетов. Это незаменимая часть, потому что её нельзя скачать. `--bzip2` сжимает архив, а `--absolute-names` сохраняет ведущий слэш, чтобы вы знали, что пути абсолютные; распаковывайте осознанно, а не в рабочий `/`. Сборка в `/tmp` с последующим копированием нужна, чтобы архив собирался на быстром локальном диске, прежде чем попасть туда, куда указывает `FOLDER`, — возможно, на медленный сетевой ресурс. `sudo` нужен потому, что многое в `/etc` читается только от root.

**`dpkg --get-selections`** записывает полный список установленных пакетов. Это перечень всего, что вы добавили поверх базовой установки, и он крошечный, потому что состоит из имён, а не содержимого.

**`update-alternatives --get-selections`** запоминает, на какую программу указывает каждая альтернатива, чтобы после восстановления `editor` оставался тем редактором, который вы выбрали, а `java` — тем JDK, который вы имели в виду.

## Восстановление

На свежей установке того же выпуска восстанавливайте в том же порядке:

```bash
# Reinstall the same set of packages.
sudo dpkg --set-selections < dpkg_selections.$HOSTNAME.txt
sudo apt-get dselect-upgrade

# Restore the alternatives.
sudo update-alternatives --set-selections < alternatives.$HOSTNAME.txt

# Put back the configuration, carefully, into a mounted target
# rather than over your running /etc.
sudo tar --extract --bzip2 --file etc.$HOSTNAME.tar.bz2 -C /mnt/newroot
```

Единственная предосторожность — последний шаг. Не распаковывайте `/etc` прямо поверх работающей системы, не посмотрев; распаковывайте в смонтированную цель или во временный каталог и переносите те файлы, которые вам действительно нужны. Версии пакетов уходят вперёд, и конфигурация от старого выпуска может сбить с толку более новый демон.

## Почему это лучше образа диска

Образ диска больше, привязан к конкретному оборудованию и разметке разделов и захватывает множество того, что вам не нужно. Эти три файла занимают несколько мегабайт, читаются человеком, переживают смену оборудования и позволяют перестроиться на более новом выпуске, читая различия, а не борясь с ними. Байты системы — забота Debian. Решения — ваши, и только решения вам и нужно хранить.
