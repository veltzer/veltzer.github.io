DONE: maybe use a better tool than mkdocs?

    Migrated to zola (single Rust binary, pinned to v0.23.3 in the workflow).

    This was not cosmetic. MkDocs' blog plugin generates its post, archive and
    pagination pages virtually, and every i18n plugin works by rewriting the
    file set before pages exist -- so the two are mutually incompatible. The
    build exited 0 while emitting ZERO post pages. That is what blocked the
    Hebrew translation, and it is why the migration happened.

    Zola gave us: per-language URLs (/he/...), per-language feeds and tag
    pages, and a language switcher generated from page.translations rather than
    hand-maintained cross-links. Adding a sixth language costs one file per
    post and no template change.

    See the "Internationalization" entry in doc/IMPROVEMENTS.md for the full
    write-up, including why mkdocs-static-i18n must not be retried.

    Confirmed: no mkdocs.yml in the repo, and the workflow installs zola pinned
    to v0.23.3.


DROPPED: Find a way to count number of visitors on each page of the
blog/site and display them.

    Removed entirely on 2026-08-19, code and all. This is not "still open" and
    should not be re-attempted without a new reason.

    What was there: a single site-wide counterapi v2 counter, incremented by
    the media pages and rendered as "Page Visits: N". It is gone --
    updateVisitorCount(), the COUNTER_* constants and the markup in
    content/media/_index.md were all deleted.

    Why dropped rather than finished:

      - The per-page half was never reachable. It needs one counter per URL,
        and counterapi's free tier caps at 5.
      - The number it did show was not trustworthy. The API is eventually
        consistent and its own updated_at stayed frozen at the counter's
        creation timestamp while the count moved; during testing it read 7,
        then 8, then 7 again.
      - A visible on-page count is a different thing from analytics, and the
        analytics need is already answered: doc/ANALYTICS.md recommends
        GoatCounter, which gives per-page figures in a dashboard without a
        cookie banner. Nothing on the page has to display a number for that
        to work.

    If a visible counter is ever wanted again, doc/ANALYTICS.md still records
    which services can and cannot do it from a static site, and why most fail
    the CORS preflight.
